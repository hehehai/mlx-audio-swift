# Voxt MLX upgrade candidate

This is a **local, unvalidated candidate**, not a published release.

## Provenance

- Working branch: `chore/voxt-model-stack-modernization`.
- Base: `v0.1.3-voxt.12`, commit `95b4587ef74e93825d3cd872a1694cab49ed0946`.
- Upstream content integrated through `3e978558404df4ad1bbb0a5634a03df2b0f9dfa5`.
- Upstream changes were squash-integrated into the candidate branch. This work is recorded as a local candidate commit; no release tag has been created and nothing has been pushed.
- README and STT test conflicts were resolved by retaining the fork contracts and the new upstream tests.

Do not start from the fork's older `main` to reproduce this candidate. Voxt requires the `.12` patches: structured `TranscriptionEvent.ended(STTOutput)`, language provenance, Qwen KV quantization/language routing, incremental Nemotron events and streaming/VAD failure propagation.

## Relevant upstream fixes

- Qwen3 ASR Slaney mel / periodic Hann frontend parity (`bf14ae0`).
- SenseVoice / FireRed fbank input scale (`b917ab5`).
- Quantized Whisper loading (`4b609fe`).
- Legacy English Nemotron checkpoint configuration/loading (`3a25c7e`).

Other upstream modules were retained to avoid maintaining a stripped-down library fork. Voxt still links only Core / STT / VAD, not TTS or STS. Removing models from Voxt's catalog does not require deleting the library's public model implementations.

## API adjustments

The new LM cache factories throw. Spark propagates the error. Marvis CSM, which explicitly consumes `[KVCacheSimple]` without a configurable cache policy, now constructs its fixed per-layer cache arrays directly instead of casting a generic factory result.

`VoxtStreamingContractTests` guards terminal structured output, language/KV settings and failure event semantics without downloading weights. The fork's existing Nemotron delay-preset tests and upstream legacy-checkpoint tests are both retained.

Voxt also needs a loader/prefill API adaptation: `ToolCallFormat.infer` no longer exists, models require `prepare()` after weight installation, and prefill settings have a typed API. The sibling Voxt checkout contains `tools/mlx-next.patch` and `tools/prepare_mlx_upgrade.py` to apply this adaptation only to an isolated validation copy. The adapter retains Voxt's prequantized layer loader and uses model-declared chat conventions for the curated checkpoints; validate tool/reasoning output and EOS behavior rather than assuming equivalence for arbitrary templates.

## Validation on Apple Silicon

Follow `Agents.md`: use Xcode so Metal libraries are built and bundled.

```bash
xcodebuild -version
xcrun swift --version # must be 6.3+
xcodebuild -downloadComponent MetalToolchain
xcodebuild -resolvePackageDependencies -scheme MLXAudio-Package
xcodebuild build-for-testing -scheme MLXAudio-Package \
  -destination 'platform=macOS' -onlyUsePackageVersionsFromResolvedFile \
  CODE_SIGNING_ALLOWED=NO
xcodebuild test-without-building -scheme MLXAudio-Package \
  -destination 'platform=macOS' -onlyUsePackageVersionsFromResolvedFile \
  -skip-testing:'MLXAudioTests/SmokeTests' -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO
```

Then validate Voxt against this local checkout as documented in its `docs/MLXAudioDependency.md`. Run Qwen dictation, SenseVoice fixtures, Whisper, MOSS/Nemotron live stop and Sortformer, as well as local LLM/VLM loading and memory benchmarks. Swift compilation, Metal execution and model accuracy have **not** been tested in the Linux preparation environment.

Only after both repos pass macOS validation: review the candidate commit, commit any fixes and the actual resolved graph, publish an immutable fork revision/tag, update Voxt's remote package and LM pins together, apply the tested Voxt API adapter, and update its dependency audit expectations. Do not point a release at an unpublished local commit or embed a developer's absolute package path in the shared project.
